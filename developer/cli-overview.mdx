The Lightdash CLI (`@lightdash/cli`) is the primary tool for integrating Lightdash into your dbt development workflow. It lets you compile metrics and dimensions from your dbt project, push them to Lightdash, spin up temporary preview environments per branch, and automate everything inside a CI/CD pipeline. Every command accepts `--verbose` for detailed output and the global `--non-interactive` flag disables all prompts so commands can run unattended.

## Installation

```bash
npm i -g @lightdash/cli
```

<Note>
Lightdash CLI is optimized for the Node.js LTS version. If you see a warning about your Node.js version, upgrade to the recommended version to avoid unexpected issues.
</Note>

## Environment variables

| Variable | Description |
|---|---|
| `LIGHTDASH_API_KEY` | API token used instead of `--token` during login |
| `LIGHTDASH_CLI_EMAIL` | Email for login (alternative to `--email`) |
| `LIGHTDASH_CLI_PASSWORD` | Password for email login (used with `--email` or `LIGHTDASH_CLI_EMAIL`) |
| `CI=true` | Equivalent to `--non-interactive`; disables all interactive prompts |

## Global options

| Flag | Description |
|---|---|
| `--non-interactive` | Disable all interactive prompts. Commands fail with a helpful error when required input is missing. |

## `lightdash login`

Authenticates the CLI against a Lightdash instance. By default, login opens a browser for OAuth. Use `--token` to bypass OAuth, which is required in CI environments.

```bash
lightdash login [url]
```

The `url` argument is flexible: a single word like `app` becomes `https://app.lightdash.cloud`, the `https://` protocol is added automatically, and any path in the URL is stripped.

<AccordionGroup>
  <Accordion title="Flags">

| Flag | Description |
|---|---|
| `--token <token>` | Log in with an API access token (bypasses OAuth) |
| `--project <project uuid>` | Select a specific project by UUID after login. Conflicts with `--skip-project-selection`. |
| `--email <email>` | Log in with email and password |
| `--oauth-port <port>` | Port for the local OAuth callback server (default: random available port) |
| `--verbose` | Show verbose output |

  </Accordion>
</AccordionGroup>

<CodeGroup>

```bash OAuth (default)
lightdash login https://app.lightdash.cloud
```

```bash API token (CI-friendly)
lightdash login https://app.lightdash.cloud \
  --token $LIGHTDASH_API_KEY \
  --non-interactive
```

```bash Short-form cloud URL
# "app" expands to https://app.lightdash.cloud
lightdash login app

# "eu1" expands to https://eu1.lightdash.cloud
lightdash login eu1
```

```bash Local development
lightdash login http://localhost:3000 --email demo@lightdash.com
```

</CodeGroup>

<Note>
In non-interactive mode (`--non-interactive` or `CI=true`), OAuth is not available. Use `--token` or set `LIGHTDASH_API_KEY`. To log in with email/password non-interactively, set `LIGHTDASH_CLI_EMAIL` and `LIGHTDASH_CLI_PASSWORD` environment variables.
</Note>

## `lightdash compile`

Compiles Lightdash resources from your dbt project — reads `target/manifest.json`, fetches the warehouse catalog, and converts dbt models into Lightdash explores. Compilation is required before deploying.

```bash
lightdash compile [flags]
```

<AccordionGroup>
  <Accordion title="Flags">

| Flag | Description |
|---|---|
| `--project-dir <path>` | The directory of the dbt project (default: current directory) |
| `--profiles-dir <path>` | The directory of the dbt profiles (default: `~/.dbt`) |
| `--profile <name>` | The profile to use (defaults to profile name in `dbt_project.yml`) |
| `--target <name>` | Target to use in `profiles.yml` |
| `--target-path <path>` | Override the dbt target directory (overrides `DBT_TARGET_PATH` and `dbt_project.yml`) |
| `--vars <vars>` | dbt variables to pass to the project |
| `--threads <number>` | Number of threads to use |
| `--no-version-check` | Skip dbt version check |
| `-s, --select <models...>` | Specify models using dbt selection syntax |
| `-m, --models <models...>` | Specify models using dbt selection syntax (alias for `--select`) |
| `--exclude <models...>` | Exclude models using dbt selection syntax |
| `--selector <selector_name>` | Use a saved dbt selector |
| `--state <state>` | Path to a directory containing a dbt state manifest |
| `--full-refresh` | Run dbt with `--full-refresh` |
| `--skip-warehouse-catalog` | Skip fetching the warehouse catalog and use column types defined in YAML |
| `--skip-dbt-compile` | Skip `dbt compile` and use the existing `./target/manifest.json` |
| `--defer` | Resolve unselected nodes by deferring to the manifest in `--state` |
| `--no-defer` | Do not resolve unselected nodes by deferring to the state manifest |
| `--favor-state` | When deferring, prioritize node definitions from `--state` |
| `--no-warehouse-credentials` | Compile without warehouse credentials (skips dbt compile + catalog) |
| `--use-dbt-list [true\|false]` | Use `dbt list` instead of `dbt compile` to generate the manifest (default: `true`) |
| `--disable-timestamp-conversion [true\|false]` | Disable timestamp conversion to UTC for Snowflake. Only use when timestamps are already UTC. (default: `false`) |
| `--verbose` | Show verbose output |

  </Accordion>
</AccordionGroup>

## `lightdash deploy`

Compiles your dbt project and deploys the resulting Lightdash explores to the active project. Can also create a new project with `--create`.

```bash
lightdash deploy [flags]
```

<AccordionGroup>
  <Accordion title="dbt project flags">

| Flag | Description |
|---|---|
| `--project-dir <path>` | The directory of the dbt project |
| `--profiles-dir <path>` | The directory of the dbt profiles |
| `--profile <name>` | Profile to use |
| `--target <name>` | Target to use in `profiles.yml` |
| `--target-path <path>` | Override the dbt target directory |
| `--vars <vars>` | dbt variables |
| `--threads <number>` | Number of threads |
| `--no-version-check` | Skip dbt version check |
| `-s, --select <models...>` | Select models |
| `-m, --models <models...>` | Select models (alias) |
| `--exclude <models...>` | Exclude models |
| `--selector <selector_name>` | Use a saved selector |
| `--state <state>` | Path to state directory |
| `--full-refresh` | Run with `--full-refresh` |
| `--defer` | Defer unselected nodes to the state manifest |
| `--no-defer` | Disable defer |
| `--favor-state` | Prioritize state definitions when deferring |

  </Accordion>
  <Accordion title="Lightdash deploy flags">

| Flag | Description |
|---|---|
| `--create [project_name]` | Create a new project. Prompts for a name if not provided. |
| `--ignore-errors` | Deploy even when there are compile errors |
| `--start-of-week <number>` | First day of the week for date functions. `0` = Monday, `6` = Sunday. |
| `--skip-dbt-compile` | Skip `dbt compile`; use the existing `./target/manifest.json` |
| `--skip-warehouse-catalog` | Skip warehouse catalog fetch; use YAML types |
| `--use-dbt-list [true\|false]` | Use `dbt list` instead of `dbt compile` (default: `true`) |
| `--no-warehouse-credentials` | Deploy without warehouse credentials |
| `--organization-credentials <name>` | Use organization credentials by name (Enterprise Edition) |
| `--disable-timestamp-conversion [true\|false]` | Disable UTC timestamp conversion for Snowflake (default: `false`) |
| `-y, --assume-yes` | Answer yes to all prompts |
| `--use-batched-deploy` | Upload explores in batches (recommended for large projects) |
| `--batch-size <number>` | Explores per batch (default: `50`, max: `1000`) |
| `--parallel-batches <number>` | Parallel batches (default: `1`, max: `50`) |
| `--gzip` | Enable gzip compression on request bodies |
| `--verbose` | Show verbose output |

  </Accordion>
</AccordionGroup>

<Tip>
For large dbt projects that hit payload size limits, add `--use-batched-deploy`. The CLI will automatically suggest this flag if a `413 Request Entity Too Large` error is returned.
</Tip>

## `lightdash generate`

Generates Lightdash schema YAML files (`.yml`) for your dbt models. Adds Lightdash metadata sections to existing schema files or creates new ones.

```bash
lightdash generate [flags]
```

<AccordionGroup>
  <Accordion title="Flags">

| Flag | Description |
|---|---|
| `-s, --select <models...>` | Models to generate (dbt selection syntax) |
| `-e, --exclude <models...>` | Models to exclude |
| `-m, --models <models...>` | Alias for `--select` |
| `--project-dir <path>` | The directory of the dbt project |
| `--profiles-dir <path>` | The directory of the dbt profiles |
| `--profile <name>` | Profile to use |
| `--target <name>` | Target to use |
| `--target-path <path>` | Override the dbt target directory |
| `--vars <vars>` | dbt variables |
| `-y, --assume-yes` | Answer yes to prompts |
| `--skip-existing` | Skip models that already have a schema file |
| `--exclude-meta` | Exclude Lightdash metadata from the generated YAML |
| `--preserve-column-case` | Preserve original casing of column names |
| `--verbose` | Show verbose output |

  </Accordion>
</AccordionGroup>

```bash
# Generate for all models
lightdash generate

# Generate for a single model
lightdash generate -s mymodel

# Generate for models with a tag
lightdash generate -s tag:sales

# Generate for a model and all its parents
lightdash generate -s +mymodel
```

## Non-interactive / CI usage

All commands support non-interactive execution for CI/CD pipelines.

```bash
# Full CI deploy: authenticate with token, skip all prompts
lightdash login https://app.lightdash.cloud \
  --token $LIGHTDASH_API_KEY \
  --non-interactive

lightdash deploy \
  --project-dir ./dbt \
  --profiles-dir ./profiles \
  --assume-yes \
  --non-interactive
```

| Scenario | Recommended approach |
|---|---|
| Project selection | Pass `--project <uuid>` to `login`, or `lightdash config set-project --uuid <uuid>` |
| Confirmation prompts | Add `-y` / `--assume-yes` to the command |
| OAuth login in CI | Not available — use `--token` or `LIGHTDASH_API_KEY` |
